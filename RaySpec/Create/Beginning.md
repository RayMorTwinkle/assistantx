# 第一步资料
## 背景
默认环境：macOS 15，CPU 为第九代 Intel i7；IDE 选用 Trae（VS Code 分支）；主力语言 Flutter / Dart；优先构建 Android 应用，其次覆盖 Web、macOS、Windows 等多端。
## 项目要解决的需求和目标人群
**核心需求：**
1. 全天候录音功能，防止错过重要内容，可作为证据和数据库
2. 语言实时转文字，记录对话和会议内容
3. 未来结合AI功能：自动分段录音、实时翻译、回答录音提问、自动记忆重要事项、自动安排日程和待办事项、唤醒词激活等

**目标人群：**
- ADHD人群（注意力缺陷多动障碍）
- 商务人群（会议记录、商务谈判）
- 学生群体（课堂记录、学习笔记）

## 项目具体设计 要求：必须包括如下内容，如果没有包含或者不够完善就再询问我：1.页面有哪几个 2.页面的功能是什么 3.内在的逻辑
**页面结构：**
1. **主页（录音界面）**：
   - 打开应用即进入录音界面
   - 显示实时转写的文本
   - 文本处理：隔几秒无新文本或文本达到一定数量时在句号处换行

2. **时间线页面**：
   - 显示录音历史记录
   - 展示录音开始时间、持续时间、结束时间
   - 左侧用时间线串联所有录音记录

3. **设置页面**：
   - 调整实时转文本的模型选择（本地模型或在线API）

**内在逻辑：**
- 应用启动后自动进入录音界面
- 录音过程中实时转写文本并显示
- 录音结束后保存到时间线
- 用户可在设置中选择转写模型

**详细功能规格：**

### 1. 录音功能细节
- **录音质量设置**：
  - **标准质量**：采样率16kHz，比特率64kbps
  - **高音质**：采样率44.1kHz，比特率128kbps
- **录音时长限制**：每15分钟隔断一次录音文件，单次最长12小时
- **后台录音**：支持应用在后台时继续录音

### 2. 文本转写功能细节
- **转写语言支持**：主要支持中文、英文
- **实时性要求**：转写延迟控制在3秒内

### 3. 数据存储和管理
- **录音文件格式**：使用AAC格式（.m4a）
- **存储容量管理**：累计存储24小时的录音文件，超过24小时的录音只保留转写文本，录音文件自动删除
- **数据导出**：支持导出录音和文本文件

### 4. 界面交互细节
- **导航方式**：底部导航栏（主页、时间线、设置）
- **录音控制**：支持暂停/继续录音功能，使用浮动按钮快速切换录音状态
- **文本编辑**：暂不考虑编辑转写后的文本
- **搜索功能**：后期实现录音文本中搜索关键词功能

### 5. 技术实现考虑
- **本地模型选择**：后期选择小巧且能利用手机NPU低功耗运行的模型
- **在线API选择**：后期可能选择讯飞等在线语音识别服务

### 6. 权限处理
- **首次启动权限**：麦克风、存储、后台运行权限
- **权限拒绝处理**：
  - 麦克风或存储权限被拒绝：退出应用并给出提示
  - 后台运行权限被拒绝：不影响主要功能，但无法后台录音

### 模块职责说明

**core/ 核心层**
- `constants/`: 定义应用常量，如录音质量设置、文件格式等
- `utils/`: 提供工具函数，如音频处理、文本格式化、文件操作
- `services/`: 封装底层服务，负责录音、转写、存储、权限等核心功能
- `models/`: 数据模型定义，确保类型安全

**features/ 功能模块**
- `recording/`: 录音功能，包含页面、组件和业务逻辑
- `timeline/`: 时间线功能，展示录音历史
- `settings/`: 设置功能，管理应用配置

**shared/ 共享层**
- `widgets/`: 可复用的UI组件
- `themes/`: 主题和样式定义

### 模块依赖关系
- `features/*` → `core/` (功能模块依赖核心层)
- `shared/` → `core/constants/` (共享组件依赖常量)
- `app/` → `features/` + `shared/` (应用层整合功能模块和共享组件)

### 模块间耦合点
1. **录音模块 ↔ 存储服务**: 修改录音格式需同步检查存储服务的文件处理逻辑
2. **转写服务 ↔ 设置模块**: 更改转写模型选择需验证转写服务的兼容性
3. **时间线模块 ↔ 录音模型**: 修改录音数据结构需更新时间线的显示逻辑
4. **权限服务 ↔ 所有功能模块**: 权限处理逻辑变更会影响所有依赖权限的功能
5. **主题系统 ↔ 所有UI组件**: 主题变更需检查所有自定义组件的样式适配
## 代码规范及约定

### 核心原则
- **简洁实用**: 保持代码简单易懂，避免过度设计
- **模块化**: 按功能拆分模块，便于维护和扩展
- **性能优先**: 关注关键性能点，如录音和转写

### 命名规范
- **文件**: `snake_case` (recording_page.dart)
- **类**: `PascalCase` (RecordingPage)
- **变量/函数**: `camelCase` (recordingDuration)
- **常量**: `UPPER_SNAKE_CASE` (MAX_RECORDING_DURATION)
- **私有**: `_privateVariable`

### 代码结构
- 单文件不超过300行
- 使用const构造函数优化性能
- 导入顺序：Dart库 → 第三方包 → 项目模块

### 开发流程
- 每次修改后运行 `flutter analyze`
- 优先使用热重载而非完整重启
- 关键功能添加简单测试

- 添加适当的震动反馈
- 使用表情符号增强界面友好度

### 响应式设计
- 800px断点适配移动端和桌面端
